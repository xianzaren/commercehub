# 常见缺陷回归测试

本轮新增 45 个可独立执行的参数化用例，加上原来的 45 个测试，完整套件共 90 项。新增用例是风险场景，不代表应用曾经存在 45 个已确认缺陷。

## 运行方式

先启动 Docker Desktop，在项目根目录运行：

```powershell
# 默认：统计 + 常见购物缺陷 + 已有交易/并发回归
.\scripts\test-merchant-analytics.ps1
# 只测统计
.\scripts\test-merchant-analytics.ps1 -Mode Analytics
# 只测购物
.\scripts\test-merchant-analytics.ps1 -Mode Commerce
# 完整测试（包括鉴权、数据库约束、迁移和端到端演示）
.\scripts\test-merchant-analytics.ps1 -Mode All
```

脚本自动构建测试镜像，失败时返回非零退出码。每次运行会重建专用 `*_test` 数据库，不应同时启动两份测试，也不能将测试连接指向真实业务库。普通业务数据不参与这些测试。

## 场景与具体示例

| 类别 | 触发示例 | 预期结果 |
| --- | --- | --- |
| 数量校验 | 加购 0、-1、10001、1.5 件 | 422，购物车与库存不变 |
| 累加库存 | 库存 5，连续两次加购 3 件 | 第二次 409，购物车仍为 3 件 |
| 订单越权 | B 查询、支付或取消 A 的订单 | 404，订单与库存不变 |
| 地址越权 | 修改、删除或使用别人的地址结算 | 404，原地址保留，不生成订单 |
| 空购物车 | 直接结算 | 409，无订单、支付、库存扣减 |
| 过期购物车 | 加购后库存减少或商品下架 | 结算重新校验，失败后无半成品订单 |
| 金额精度 | 单价 0.10，购买 3 件 | 金额精确为 0.30 |
| 历史快照 | 下单后改商品名、售价、收货地址 | 原订单商品与地址快照不变化 |
| 重复取消 | 未付款/已付款订单连续取消两次 | 库存只恢复一次，已付款记录标为退款 |
| 取消后支付 | 对已取消订单付款 | 409，不产生成功支付 |
| SKU 校验 | 不选规格、传其他商品的规格 | 422/404，不写入订单 |
| SKU 共享库存 | 两规格分别购买 3 和 3 件，总库存 5 | 拒绝超额；改为 3+2 可成功且库存为 0 |
| SKU 下架 | 加购后所选规格停用 | 结算 409，库存不扣减 |
| 收藏幂等 | 重复收藏、重复取消收藏 | 不重复插入，不影响其他账号 |
| 搜索记录 | 大小写、前后空格、空白词、匿名请求 | 规范化计数，空白及匿名请求不计入个人历史 |
| 查询参数 | 页码 0、页容量 101、倒置价格区间、超长词 | 422 |
| 地址空值 | PATCH `{"is_default": null}` | 422，而非服务器 500；原地址不变 |
| 重复结算 | 同一购物车同一请求再次提交 | 不重复下单或扣库存；当前空购物车允许返回 409，不宣称已实现完整结算重放 |
| 订单状态矩阵 | 已付、处理中、已发货、完成、取消、待付 | 只有前四种有效成交计入图表 |
| 支付状态矩阵 | PENDING / FAILED / REFUNDED | 均不计入销售额、订单量与排名 |
| 日期连续性 | 闰日、跨月、跨年、90 天 | 日期不漏不重，每日之和等于总指标 |
| 历史经营数据 | 商品改价、改名、软删除 | 历史成交金额保留，名称使用当前名称 |
| 店铺隔离 | 传别家 store_id 参数 | 不改变登录商家的统计范围 |
| 商家停用 | 已持有 Token 的商家被冻结 | 原 Token 无法继续访问统计接口 |
| 零销量商品 | 筛选本店无成交商品 | 指标全部为零，不回退到全店数据 |

此外默认套件沿用已有的事务中途故障回滚、两客户争抢最后一件商品、支付重试与金额不匹配等测试，不将它们冒充本轮新增用例。

## 本轮确认的缺陷与测试误报

### BUG-004：地址布尔字段 null 导致 500

已登录顾客向自己的 `/api/addresses/{id}` 提交 `PATCH {"is_default": null}`。原请求模型允许 null，但数据库不允许，实际返回 500。修复在请求模型校验阶段拒绝 null，返回 422；省略该字段仍支持部分更新，显式 false 仍有效。

回归用例：`test_null_default_address_is_validation_error_not_server_error`。

### TEST-005：匿名测试实际携带登录 Cookie

TestClient 会保留登录接口设置的 Cookie，仅省略 Authorization 不等于匿名。原测试误认为搜索被多计一次。修复为发送匿名请求前清空测试客户端 Cookie；应用仍正确支持 Cookie 登录。

## 验证结果（2026-09-29）

完整套件 90 项通过，后端行覆盖率 90.90%，达到 CI 的 75% 要求。1 条第三方 Starlette/AnyIO 弃用警告不影响执行。

另修复测试环境重建故障：多 SKU 数据无法降级到旧版“每个商品一条明细”的唯一约束。测试初始化改为校验 `*_test` 库名后清理该库内表，再执行 Alembic 升级；迁移显式使用测试连接，支持从上次中断的测试状态恢复。它不改变生产迁移的降级规则。

## 验收范围

这是 API、业务和数据库回归，不是完整浏览器自动化、安全渗透或高并发压测。测试通过不等于没有其他缺陷。此前商家图表的浏览器验收见 `merchant-analytics-and-bugs.md`。
